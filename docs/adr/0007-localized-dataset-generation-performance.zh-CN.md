# 本地化数据集生成采用带索引的顺序处理

[English](0007-localized-dataset-generation-performance.md)

## 背景

本地化数据集生成会读取大型 `d4data` 检出目录并生成 D4LF JSON 资源。词缀阶段原本是主要
耗时点，因为它解析每个 Power JSON 文件，只为构建 Power SNO 标识到名称的映射。生成器
的进度输出也很粗略，只说词缀阶段较慢，没有实际计时。

实验使用相同的 `enUS` 检出目录，并在每次运行后验证生成文件的 SHA-256。按文件使用线程池
以及并行执行互不依赖的顶层阶段，在目标 Windows 机器上都更慢，因为负载主要受本地文件
I/O 和解析开销限制。

## 决策

- 存在 `CoreTOC.dat.json` 时，使用其第 `29` 节作为 Power SNO 到名称的索引。
- 索引不可用时，回退到扫描 Power JSON 文件。
- 数据集阶段和逐文件处理保持顺序执行，不根据基准实验提供工作线程数或自动调优选项。
- 输出低频的 `START`/`FINISH` 阶段消息，包含源文件数量和耗时。
- 在一次生成运行期间缓存本地化 Power 名称投影。
- 保持确定性的遍历、JSON 序列化、输出顺序和原有失败行为。

## 证据

2026-07-23，在三个预热后的同进程运行中，带索引的顺序实现完成全流程约需 0.80 秒，变更前
约为 1.88 秒。词缀阶段从约 1.48 秒降至 0.56 秒。加入索引后，单线程实验平均约 0.80 秒，
2 或 4 线程约 1.08 秒，8 线程约 1.09 秒，16 线程约 1.12 秒。所有生成文件哈希均与基线一致。

## 影响

当前 `d4data` 检出目录生成数据时不再解析数千个 Power 文件，并能显示时间消耗位置。缺少
CoreTOC 索引时仍保留原有行为。对当前负载而言，并行执行仍是被拒绝的优化；如果源格式或
硬件变化，可使用阶段计时和输出哈希作为回归保护后重新评估。
