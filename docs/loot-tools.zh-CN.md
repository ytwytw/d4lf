# 战利品工具

在主界面点击 **战利品工具**，可打开游戏过滤器生成器、完整物品导出或装备资料库。
每个 Profile 行的 **工具** 菜单也可直接打开关联该 Build 的过滤器或装备资料。

安装、升级和回退见 [README](../README.md#%E7%AC%AC-15-%E8%B5%9B%E5%AD%A3%E7%89%88%E6%9C%AC%E4%B8%8E%E5%8D%87%E7%BA%A7)。生成器和资料库可离线使用；
完整物品导出需要 Windows 上正在运行并已连接 TTS 的游戏。

## 游戏过滤器

选择已保存的 Profile，再点击 **从所选 Profile 生成新副本**。重新生成会先处理未保存修改，
生成结果另作副本，不会覆盖已有的游戏过滤器文件。Build 导入会保存来源网址、变体身份与名称；
既有 Profile 没有这些资料时不会根据文件名猜测。

默认采用保守的兼容策略。D4LF 的部分规则（例如未解锁外观、圣化装备保护、数值百分比）
不能在游戏过滤器中完全表达；窗口会列出放宽的条件，并明确显示当前是否会隐藏物品。
需要按 Build 筛选掉落装备时，可以勾选对应选项后重新生成。该选项只影响新生成的游戏过滤器。

也可以不关联 Profile：新建独立过滤器，或者粘贴游戏导出的代码。规则可添加、编辑、排序、
启用或停用；可设置名称、显示／隐藏／改色动作以及物品强度、稀有度、部位、词条、暗金等条件。
游戏按顺序匹配规则，最多支持 25 条；超限不会偷偷截掉保留条件。

点击 **保存** 保存可继续编辑的文档；点击 **复制游戏代码** 或 **导出 TXT** 后，
在游戏的战利品过滤器界面导入。D4LF 不会自动替换当前游戏过滤器。
导入包含未知字段或语义的代码时，原文会保留，不能安全改写的内容会限制编辑。

保存的可编辑文档是 JSON，默认目录为 `%USERPROFILE%\.d4lf\native_filters`，也可在保存窗口另选位置。
游戏使用的是 **复制游戏代码** 或 **导出 TXT** 得到的代码，不是这个 JSON 文件。
Profile 修改后，需要重新生成副本、核对差异并在游戏中再次导入，已有游戏过滤器不会自动同步。
独立文档及已导入代码不要求存在关联 Profile；关联信息只记录已保存的来源，不补猜缺失的 Build 或 Variant。

建议使用简短的过滤器名称；过长的名称可能被游戏替换为默认名称。
游戏可能为未填写的物品强度上限采用默认值；例如在游戏 `3.2.2.73764` 中，
只设置最小值 100 的规则显示为 100～900。导入后请检查实际条件。

游戏过滤器决定地面物品的显示方式；原有 D4LF Profile 仍用于识别后判断保留、标记等操作。
生成器的提示是两套规则之间的差异说明，不能当作“所有规则完全等价”的保证。

## 完整物品导出

1. 进入要盘点的角色，在城镇打开仓库，等待 D4LF 的 TTS 状态显示已连接。
1. 结束其他游戏自动操作，关闭巅峰悬浮层、信息面板和诊断录制。
1. 点击 **战利品工具 → 完整物品导出**，只需选择 Markdown、TXT 或 JSON。
1. 点击 **开始导出**，保持游戏前台，扫描期间暂时不要移动鼠标。
1. 完成后点击 **打开导出文件**。文件默认保存在 `%USERPROFILE%\.d4lf\exports\inventory`。

扫描范围包括可识别的开放仓库页、五类背包（装备、神符、镶嵌物、消耗品、钥匙）、当前穿戴装备，
以及护符／封印面板。
收藏、垃圾和无法解析的物品也会记录；不移动、不装备、不使用、不出售、不分解物品。
如果“仅视觉模式”已启用，需要先关闭它，因为翻页扫描需要点击游戏页签。
这一步只为启动扫描；不要同时触发过滤或物品移动热键。扫描结束后，可恢复“仅视觉模式”。
需要停止时，点击 **取消并保存已读取物品**，等待保存结束；再次开始会生成新的快照，不会续写上一份。

文件保留每件物品的位置、完整接收到的原始说明、可识别属性、标记，以及无法读取或解析的原因。
即使现有词库不认识某件新物品，也会保留完整原文，并单独记录能直接读出的名称、类别、强度、数量、
等级要求、耐久度、回火次数和说明行；没有读到的字段保持未知。
字面观察也可记录原文中明确给出的品质及加成，以及纯数字开头的百分比说明行；这些说明行不自动区分
固有、随机、回火或精铸词条。空插槽文字的出现次数不等于总插槽数，也不能确定已镶嵌物的内容。
同名同属性的两件物品按不同位置分别保存。缺失字段不会填写成猜测值；解析成功也不表示所有可见文字
均已结构化。无法访问的页面或未确认的空槽会出现在覆盖记录中。

“完成”表示本次预定范围没有报告访问问题，所记录物品的 TTS 原文通过了完整性检查。
它不证明 TTS 播报了屏幕上的每一项信息。未能映射到现有词库的数量会单独提示，
文件仍保留各件物品的解析状态和原因；原文缺失、截断或页面扫描失败则显示“部分完成”。

取消、失去游戏焦点、TTS 断开或中途失败时，会保存已读取的部分结果并标明状态。
MD、TXT 和 JSON 使用同一个快照；可读格式同时附完整结构化数据，方便交给外部 AI 分析。
应用内部只负责导出，没有 AI 分析或上传步骤。

只有当前物品的 TTS 标题明确标注收藏时，导出的 `favorite` 才为 `true`，否则为 `null`。
没有收藏播报不能据此判定“未收藏”。槽位视觉判断只保留为未验证的 `favorite_evidence`，
不覆盖已确认收藏状态。

### 如何阅读状态和未知字段

| 显示／字段                 | 含义与处理                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| 完成 / `complete`          | 本次采集完成；仍需查看未映射数量和字段值，不能据此推断全部字段已结构化。                 |
| 部分完成 / `partial`       | 至少有范围、采集或界面恢复问题；查看 `issues` 和各范围的 `errors` 后重新扫描。           |
| 已取消 / `cancelled`       | 保留停止前的结果；未访问范围不是空库存。                                                 |
| 扫描失败 / `failed`        | 扫描在取得物品前失败；若保存路径也不可写，可能没有可打开的文件。                         |
| `unparsed` / `parse_error` | 物品未映射或解析出错；结合 `capture_complete`、`truncated` 和 `error` 判断原文是否完整。 |
| `null` / `unknown`         | 没有可靠读数，不代表零、否、没有插槽或没有属性。`game_build` 未确认时也保持 `unknown`。  |
| `favorite`                 | 当前 TTS 标题明确标注收藏时为 `true`，否则为 `null`；未知不能当作未收藏。                |
| `favorite_evidence`        | 保留收藏判断的来源；槽位视觉判断标为 `unverified`，不能据此覆盖已确认状态。              |

JSON 顶层包含程序版本、语言、开始／结束时间、`scopes`（覆盖范围）、`items`（物品）和 `issues`。
每件物品的 `location` 区分仓库／背包／穿戴及具体位置；`raw_tts`、`raw_events` 保留采集证据，
`parsed` 是词库解析结果，`observed_fields` 是直接从原文读取的字段。MD、TXT 末尾也附带同一完整数据，
不要只看前面的可读摘要。

“恶毒”威能和“巨人贡品”各自对应不止一个物品身份，裸名称不能用于唯一识别。
消歧需要同一件当前物品的完整、已核验效果说明；缺少说明、截断或同时出现冲突效果时仍应保留为未知。

## 装备来源与词条

资料库可独立按中文、英文和装备部位搜索，也可从 Profile 的工具菜单查看其中明确指定的装备。
普通装备部位规则不会被当成某件暗金需求；Build 正文中的替代装备需要单独搜索。

装备详情展示来源记录、物品描述、固有词条、主要词条身份、可选词条组、职业差异与浮动范围。
固定的词条身份不代表其数值固定，也不假设每件装备都有两个固定词条。
数据缺失的掉落地点、译名和概率会明确显示为未知；资料不构成掉落保证。

当前装备参考资料版本为 **3.2.1.73552**，快照日期为 **2026-10-05**。
它不一定与当前游戏版本一致，也不会自动更新掉落表；请结合当前赛季的游戏说明使用。

资料来自随包保存的版本化快照，界面显示数据版本和日期。英文扩展字段可能比中文先更新，
因此会分别展示两种语言，并保留来源信息。资料库与实时库存的数值分开，不用资料库范围替代实际物品读数。
当前资料库不包含普通传奇装备的完整获取资料。搜索不到某件装备或关联列表为空，不表示它不存在或无法掉落。
来源和锁定版本见[资料来源说明](../assets/equipment_knowledge/NOTICE.md)；资料库不会联网刷新掉落表。

## 本地文件与隐私

配置、Profile、默认保存的过滤器和库存快照都在 `%USERPROFILE%\.d4lf` 下；自行另选路径的文件需另外备份。
库存导出与装备资料浏览不上传数据，也不连接外部 AI。导出文件可能包含角色库存、位置、原始游戏播报等私人信息。
诊断留样和日志还可能包含画面、路径或错误详情。分享前请检查并脱敏，无需提供整份个人库存或 `.d4lf` 目录。

## 使用限制

- 导出以游戏 TTS 实际播报为准，不会自动用截图补齐字段，也不读取游戏内部物品状态。
- 已镶嵌内容、隐藏属性或未播报的状态可能无法取得；未知值不代表零或不存在。
- 完整原文不等于全部字段都已结构化。提交给外部 AI 时，请保留原文、状态和未知字段。
- 名称冲突或缺少完整效果的物品保持未知；资料中列出的物品不保证当前赛季可以掉落。

## 故障排查

| 现象                                 | 建议                                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 没有“战利品工具”入口                 | 核对程序显示的版本和实际启动路径；从完整候选／发行包的新目录启动，避免仍在运行旧 EXE。                            |
| 提示先进入角色或等待连接             | 进入角色，启用游戏屏幕阅读器与第三方屏幕阅读器，并确认 DLL 安装及语言设置；等待 TTS 连接后重试。                  |
| 提示另一项操作运行中，或要求关闭面板 | 停止过滤／移动任务，关闭巅峰悬浮层、信息面板和诊断录制；一次只启动一项游戏操作。                                  |
| 找不到仓库页或背包分类               | 在城镇打开仓库，关闭遮挡面板；检查游戏显示设置。无法确认的页面会记录为不可用，不会被当作空页。                    |
| TTS 持续播报、焦点丢失或扫描中断     | 保留部分结果，停止其他输入和连续环境播报后重新开始；不要将两次扫描误认为同一时刻的完整库存。                      |
| 文件保存失败                         | 检查目标目录权限与可用空间，关闭正在占用该文件的程序；保留已有快照后重新导出。若出现 `.tmp`，不要当作已完成快照。 |
| 游戏拒绝过滤器代码                   | 使用复制／TXT 中的完整代码，缩短名称，检查规则数和兼容提示；未知语义限制编辑时保留原文，不强行修改。              |
| 装备资料库不可用                     | 检查是否完整解压随包资源；重新解压同一版本完整包，避免拼接不同版本的 EXE 和 assets。                              |

报告问题时提供程序版本、游戏版本（若已确认）、语言、显示设置、操作步骤及脱敏错误信息。
先检查对应范围和物品的失败原因，无需公开整份个人库存。
